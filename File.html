Eliminating accidental triggers in eye-scrolling using n × m binning and intent detection.

The "Midas Touch" Problem

In current eye-tracking interfaces, the system struggles to distinguish between observing and acting.

  • Accidental Activation: Users looking at the bottom of the screen to read are interpreted as trying to scroll.
  • User Frustration: This creates a "jittery" experience where content moves when it should stay still.
  • Current Solution: "Dwell Time" timers make the UI feel sluggish and unresponsive.
⚠ UNINTENDED SCROLL TRIGGERED

The Paradigm Shift: Intent Detection

👁️ Observational Intent

User is absorbing information. Interaction should be paused.

↕️

🖱️ Navigational Intent

User wants to change the state of the UI (Scroll/Swipe).

We are moving from a reactive model ("Gaze = Scroll") to a predictive model ("Gaze + Context = Intent").

  • The Engine: An Intent State Machine running in the background.
  • The Heuristic: We use visual complexity as the primary predictor of user intent.
  • The Output: A real-time confidence score determining if the user wants to read or scroll.

Visual Context = User Intent

📝

High Contrast

Text blocks, detailed textures, and high-frequency patterns indicate the user is reading.

ACTION: INHIBIT SCROLL
⬜

Low Contrast

Margins, gutters, white space, and smooth UI zones indicate the user is looking to navigate.

ACTION: ENABLE SCROLL

Spatial Quantization (n × m Binning)

Calculating contrast on a per-pixel basis is computationally expensive and highly sensitive to noise.

  • Grid Division: The viewport is divided into an n × m grid (e.g., 32x32 blocks).
  • Data Aggregation: We calculate the average luminance variance for each discrete bin.
  • Stability: Gaze coordinates (x, y) are mapped to a specific bin (i, j), providing a smoothed intent signal.

Red = High Contrast (Text). Green = Low Contrast (Margins). Dot = Gaze.

The Algorithm Pipeline

📊

Retrieve the pre-calculated contrast/luminance score for bin(i, j).

⚙️

3. Assess Intent

Pass the bin score through the Intent State Machine to scale the "Scroll Friction".

Technical Integration

🖥️
GPU VRS PIPELINE

Hardware Synergy

This approach aligns perfectly with modern GPU rendering techniques.

  • Variable Rate Shading (VRS): GPUs already divide frames into tiles (e.g., 16x16 pixels) to determine shading rates. We reuse this exact grid for our bins.
  • Zero Computation Overhead: The contrast maps are generated for rendering optimization anyway; the Intent Engine simply reads the existing buffer.
